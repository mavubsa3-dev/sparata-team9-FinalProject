## 카테고리 목록 조회 캐싱 적용

### 적용 배경
카테고리는 관리자에 의해서만 가끔 변경되고, 사용자 요청으로는
빈번하게 조회되는 데이터로, 캐싱 적용에 적합하다고 판단하여 도입했다.

### 구현 과정
Spring Cache 추상화와 Caffeine을 활용해 로컬 캐시를 구성했다.
CategoryService.getCategory()에 @Cacheable을 적용해 조회 결과를 캐싱했고,
생성/수정/삭제 시점에는 @CacheEvict로 캐시를 즉시 무효화하여
데이터 최신성을 보장했다. TTL은 10초로 설정했다.

### 성과
캐시 미스(DB 조회) 평균 9.4ms, 캐시 히트(캐시 조회) 평균 3.7ms로,
약 2.5배의 응답 속도 개선을 확인했다.

k6를 이용해 동시 사용자 50~300명 규모의 부하테스트를 진행한 결과,
캐싱 적용 후 평균 응답시간이 2.01ms → 0.58ms로 약 3.5배,
p(95) 응답시간은 3ms → 1ms로 약 3배 개선되었다.
